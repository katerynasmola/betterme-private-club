# BetterMe Private Club — Check-In

Форма чек-іну на два заходи (Kyiv 15 серпня, Warsaw 29 серпня). Людина вводить кілька букв імені чи прізвища, обирає себе зі списку — список підтягується напряму з Google Таблиці, тож його можна редагувати без змін коду. Після чек-іну навпроти імені в таблиці зʼявляється статус "Checked In".

**Сайт хоститься самим Google Apps Script** (не GitHub Pages) — це потрібно, щоб працювало обмеження доступу "лише для акаунтів betterme.world". Цей репозиторій — вихідний код і історія змін; сам робочий інструмент живе в Apps Script вашої Google Таблиці.

## Структура проєкту

- `apps-script/Code.gs` — серверна логіка: віддає список імен, приймає чек-іни.
- `apps-script/Index.html` — HTML-шаблон сторінки (лого вбудовано як base64, без зовнішніх файлів).
- `apps-script/Stylesheet.html` — стилі.
- `apps-script/JavaScript.html` — клієнтський скрипт (автозаповнення, звернення до сервера через `google.script.run`).
- `assets/logo.png` — вихідний файл лого (про запас, на випадок майбутніх правок; сам сайт використовує вбудовану копію в Index.html).

## Крок 1. Структура вкладки з іменами

Вкладка **"Private Club Kyiv | Registration (landing)"** у Google Таблиці має такі колонки:

| A (Ім'я) | B (Kyiv Check-in) | C (Kyiv Timestamp) | D (Warsaw Check-in) | E (Warsaw Timestamp) |
|---|---|---|---|---|
| Kateryna Smola | Checked In | 2026-08-03 12:04 | | |

- **Щоб додати нову людину** — просто впиши її ім'я в наступний порожній рядок колонки A. З'явиться в автозаповненні одразу (сайт щоразу підвантажує актуальний список).
- Колонки B–E скрипт заповнює сам під час чек-іну, вручну їх чіпати не треба.
- Якщо перейменуєш вкладку — онови значення `NAMES_SHEET_NAME` на початку [apps-script/Code.gs](apps-script/Code.gs).

## Крок 2. Розгортання в Apps Script

1. Відкрий свою Google Таблицю.
2. Меню **Розширення (Extensions) → Apps Script**.
3. У редакторі створи 4 файли з такими самими назвами й типами, як у папці `apps-script/` цього репозиторію, і встав відповідний вміст:
   - `Code.gs` (тип Script)
   - `Index.html` (тип HTML)
   - `Stylesheet.html` (тип HTML)
   - `JavaScript.html` (тип HTML)
4. Збережи проєкт (значок дискети).
5. **Deploy → New deployment**.
   - Тип: **Web app** (клацни на шестерню біля "Select type", якщо не бачиш цей вибір одразу).
   - Execute as: **Me**.
   - Who has access: **Anyone within betterme.world** (щоб тільки співробітники з робочим Google-акаунтом могли відкрити сторінку).
6. Натисни **Deploy**, підтверди дозволи (Authorize access) — це твій обліковий запис, доступ буде лише в скрипта до цієї таблиці.
7. Скопіюй **Web app URL** (виглядає як `https://script.google.com/macros/s/XXXXX/exec`).

Посилання на конкретні події — той самий URL з різним `?event=`:

- Kyiv: `https://script.google.com/macros/s/XXXXX/exec?event=kyiv`
- Warsaw: `https://script.google.com/macros/s/XXXXX/exec?event=warsaw`

Автоматично з'явиться вкладка **Responses** — лог усіх чек-інів (дата/час, ім'я, подія) про всяк випадок, окрім живого статусу в колонках B–E.

> Якщо потім зміниш код у Apps Script — треба зробити **Deploy → Manage deployments → Edit (олівець) → Version: New version → Deploy**, інакше зміни не застосуються. URL при цьому лишається тим самим.

## Про доступ "Anyone within betterme.world"

Коли людина відкриває посилання, Google спершу попросить увійти робочим акаунтом (@betterme.world), якщо вона ще не залогінена — і лише після цього покаже форму чек-іну. Це і дає реальний захист (не просто "хто має посилання", а саме "хто має робочий акаунт компанії").

## Як це працює

1. При завантаженні сторінки клієнтський код викликає серверну функцію `getNames()` і отримує актуальний список імен з колонки A.
2. Людина вводить кілька букв — список фільтрується на льоту.
3. Після вибору імені та натискання «Check In» викликається серверна функція `checkIn(name, event)` — `event` визначається параметром `?event=` в URL сторінки.
4. Apps Script знаходить рядок з цим іменем і проставляє "Checked In" + час у відповідні колонки (Kyiv або Warsaw), а також дописує рядок у лог `Responses`.
